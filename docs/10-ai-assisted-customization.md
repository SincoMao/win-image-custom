# 第 10 章 使用 AI 工具完成定制

本章说明如何借助具备终端执行能力的 AI 编程助手（Claude Code、Cursor 等）驱动本
仓库完成镜像定制。内容分为三个部分：任务原理与分工、环境准备、提示词规范
（含可直接使用的标准模板）、结果验收。

## 10.1 任务原理与分工

将本任务交给 AI 执行时，首先需要明确分工：

- **本仓库是规格说明书**。`config.ps1` 集中全部可变参数，`docs/` 各章精确描述
  每个步骤的行为、清单与已知故障机理。AI 的职责是"严格按规格执行、监控执行
  过程、在偏离规格时报告"，而不是重新设计定制方案。
- **AI 适合承担的工作**：按文档驱动流水线、读取日志定位失败、在新版介质发布
  时做差异适配（版本名变化、组件路径变化等）。
- **AI 不适合自主决定的工作**：增删定制清单项、引入本仓库之外的工具、修改
  约束红线。这类变更必须由人发起并以显式指令下达。

明确这一分工的原因：镜像定制是低容错任务，AI 的"创造性补全"在此场景中是
风险来源而非价值来源。提示词设计的核心目标是约束 AI 严格对齐规格。

## 10.2 环境准备（人执行的部分）

以下事项不应委托给 AI，由人预先完成：

1. **建立专用任务目录**。每次定制使用独立目录，例如 `D:\Win11-25H2\`，
   将微软官方 ISO 下载至该目录。目录专用可避免 AI 误操作无关文件。
2. **克隆本仓库**到本地（例如 `D:\win-image-custom\`）。
3. **安装 Windows ADK 部署工具**（见第 1 章）。也可以交由 AI 先执行探测
   （脚本启动时会自动探测 oscdimg 并报告缺失），但安装动作建议人完成。
4. **以管理员身份启动终端，再在该终端内启动 AI 工具**。AI 工具继承启动
   它的终端的权限上下文；DISM 挂载、注册表配置单元加载均要求提权。
   若 AI 运行在非提权终端，一切离线服务操作都会失败。
5. **确认版本名**。执行 `Get-WindowsImage` 查看 ISO 索引表，确定
   `$EditionName` 的准确取值（见第 2 章 2.1 节）。

## 10.3 提示词设计原则

以下八条原则按重要性排序，适用于全部场景模板。

### 原则一：指定唯一事实来源

明确要求 AI 以本仓库的脚本与文档为唯一依据，禁止引入任何第三方精简工具、
优化脚本或来自网络的注册表"技巧"。本任务的正确解已经存在，AI 不需要搜索
外部方案。

### 原则二：先读后做

要求 AI 在动手前先阅读 `config.ps1`、`docs/02`、`docs/03`、`docs/09`，
复述任务流程与关键约束，经人确认后再执行。未读规格即执行是镜像定制类
任务最常见的失败起点。

### 原则三：分步执行，单变量修改

要求 AI 一次只运行一个步骤脚本，检查退出码与日志后再进入下一步；出现故障
时，每次只修改一处并说明修改假设，禁止连环变更。流水线脚本均幂等，
单步重跑是安全的。

### 原则四：输入显式化

ISO 路径、版本名、需要变更的开关取值，全部写进提示词正文。凡是 AI 需要
"猜"的参数，都是潜在的错误源。

### 原则五：红线复述

将第 7 章的约束红线直接纳入提示词（或明确要求 AI 阅读 `docs/07` 并在执行
中遵守）。重点是：禁止 `/startcomponentcleanup` 与 `/resetbase`，不动 WinSxS，
不停 `mpssvc`/`BFE`/`wuauserv` 等红线服务，不触碰激活相关内容。

### 原则六：以验证为完成标准

任务完成的唯一判定标准是 `06-verify.ps1` 退出码为 0 且输出
`ALL VERIFICATION CHECKS PASSED`。脚本语法通过、命令执行无报错、文件已生成，
均不构成完成标准。

### 原则七：已知陷阱前置

`docs/09` 收录了本任务的全部已知陷阱（DISM 参数名、PowerShell 5.1 的 stderr
陷阱、Defender 键 ACL、UTF-8 BOM、提权与重定向冲突）。在提示词中明确要求
AI 阅读该章，可避免其在已解决的问题上重复试错。

### 原则八：要求结构化交付

要求 AI 在结束时输出：产物路径、日志路径、验证结果摘要，以及**执行过程中
对规格的一切偏离清单**（例如跳过了某个缺席目录、回退了某个引导文件）。
偏离清单是人工复核的重点。

## 10.4 场景 A：驱动现成流水线（推荐）

适用于版本名与默认开关无需调整、仅更换源 ISO 的情形。这是最稳妥的使用方式，
AI 仅负责执行与监控。

```text
任务：使用 D:\win-image-custom\ 仓库中的流水线，将 D:\Win11-25H2\Win11_Pro.iso
定制为开发机镜像。

执行前必须完成：
1. 阅读 D:\win-image-custom\config.ps1、docs\02-configuration.md、
   docs\03-pipeline.md、docs\07-design-anti-revival.md、
   docs\09-troubleshooting.md，然后向我复述执行流程与约束红线，待我确认后再继续。
2. 将 config.ps1 中的 $IsoPath 改为 D:\Win11-25H2\Win11_Pro.iso，
   $EditionName 改为 "Windows 11 专业版"，其余开关保持默认。
   注意：config.ps1 必须以 UTF-8 with BOM 编码保存，修改后验证 BOM 仍然存在。

执行要求：
3. 以 D:\win-image-custom\run-all.ps1 为唯一入口执行，禁止自行拼装 DISM 命令，
   禁止引入任何第三方工具或脚本。
4. 逐阶段检查 D:\ISO-Work\Logs\customize.log；任一 [FAIL] 出现即停止，
   引用日志原文向我报告，每次只提出一处修改建议，经我确认后再改。
5. 遵守 docs\07 中的全部约束红线。

完成判定（缺一不可）：
6. run-all.ps1 退出码为 0，D:\Win11_Dev.iso 已生成；
7. 执行 D:\win-image-custom\06-verify.ps1，退出码为 0 且输出
   ALL VERIFICATION CHECKS PASSED；
8. 输出：产物路径、产物大小、日志路径、执行中对规格的全部偏离事项。
```

## 10.5 场景 B：新版介质的差异适配

适用于新版本 Windows 11 发布后，介质结构或组件路径发生变化的情形
（典型现象：01 步报版本名匹配失败，或 03 步报告某摘除项路径异常）。

```text
任务：流水线在 <粘贴报错日志原文> 处失败，疑似新版介质差异。

要求：
1. 只诊断、先不修改任何文件。列出全部相关证据：
   - ESD/WIM 的完整索引表（dism /get-wiminfo 原文）；
   - 挂载映像中相关路径的实际存在情况。
2. 对照 docs\08-maintenance-new-builds.md 第 8.3 节的差异点表，给出结论：
   属于哪一种已知差异，或确认为新差异。
3. 若为版本名变化：仅修改 config.ps1 的 $EditionName（保持 UTF-8 BOM），
   重跑流水线。
4. 若为组件路径变化：提出对 03-customize.ps1 清单与 06-verify.ps1 断言的
   最小修改方案，以及 docs\05 清单的登记内容，经我确认后执行。
5. 完成后以 06-verify.ps1 全过为判定标准。
```

## 10.6 场景 C：调整定制内容

适用于需要增减开关或清单项的情形（例如新增一个要禁用的服务、追加一个要
删除的目录）。要点：

1. 变更必须以人的明确指令发起，禁止 AI 自行扩展清单（白名单制原则，
   见第 8 章 8.4 节）；
2. 每一处清单变更必须三处同步：执行清单（03-customize.ps1）、验证断言
   （06-verify.ps1）、文档登记（docs/04 或 docs/05）；
3. 新增服务禁用项前，先核对不在 `$ProtectedServices` 之列；
4. 完成后同样以 06-verify 全过为判定标准。

## 10.7 结果的人工检查点

AI 报告完成后，人必须亲自复核以下各项，不得仅凭 AI 的完成声明验收：

| 检查点 | 方法 | 通过标准 |
|---|---|---|
| 验证结果 | 查看 06-verify 输出原文 | `ALL VERIFICATION CHECKS PASSED`，退出码 0 |
| 日志完整性 | `customize.log` 检索 `[FAIL]` | 仅存在已解释的早期失败记录 |
| 脚本改动 | `git -C D:\win-image-custom diff` | 每一处改动均可说明理由 |
| 配置文件 | 检查 `config.ps1` 首三字节 | BOM 存在（`EF BB BF`） |
| 产物内容 | 挂载产物 ISO | `autounattend.xml`、单一 install.wim、无 install.esd |
| 装机验收 | Hyper-V 虚拟机全新安装 | 通过第 6 章全部验收项 |

## 10.8 AI 执行的典型失败模式与对策

| 失败模式 | 表现 | 对策 |
|---|---|---|
| 未读规格即执行 | 跳过配置直接运行命令 | 原则二：先复述流程，经确认再动手 |
| 引入外部方案 | 下载第三方精简工具、粘贴来源不明的注册表脚本 | 原则一与原则五：唯一事实来源 + 红线 |
| 参数臆测 | 虚构 DISM/oscdimg 参数、虚构文件路径 | 要求所有命令引用真实输出；指向 docs/09 |
| 连环修改 | 一次报错后同时改动多处，无法归因 | 原则三：单变量修改，每处改动先说明假设 |
| 破坏文件编码 | 编辑 config.ps1 后 BOM 丢失，中文版本名乱码 | 提示词显式声明 BOM 要求 + 10.7 检查点 |
| 非提权执行 | DISM 报"需要提升权限"后反复重试 | 10.2 第 4 条：提权终端内启动 AI |
| 未验证即宣布完成 | 以"命令执行成功"代替验证 | 原则六：06-verify 退出码为唯一完成标准 |
| 隐瞒偏离 | 静默跳过异常项并在总结中宣称全部成功 | 原则八：强制输出偏离清单并逐项人工复核 |
