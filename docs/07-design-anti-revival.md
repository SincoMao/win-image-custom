# 第 7 章 防复活设计与约束红线

## 7.1 问题背景

Windows 安全组件具有多层次的自恢复机制：安全智能更新可能重置策略键，服务控制
管理器可能被策略刷新，二进制可能被累积更新补齐。单点修改（例如只改一个策略键）
在下一次更新后即失效。本工具的设计目标是：定制结果在常规补丁周期内稳定存在，
且不破坏系统接受后续更新的能力。

## 7.2 三层冗余结构

```
第 1 层  策略层   Policies\* 键关闭 Defender / SmartScreen / 防火墙过滤
   │             └─ 即使被安全智能更新重置 ↓
第 2 层  服务层   8 个 Defender 相关服务 Start=4，拒绝启动
   │             └─ 即使服务配置被重置 ↓
第 3 层  二进制层  Defender 引擎双实例、驱动、计划任务、SecHealthUI 均已摘除，
                   无可执行程序存在
```

三层相互独立，任意单层被外部机制恢复都不影响另外两层生效。三层同时被完整恢复
才可能出现 Defender 复活，而常规更新通道不存在这样的恢复动作。

## 7.3 与 Windows Update 的关系

- **月度累积更新（LCU）**：以组件化方式替换文件，不会重建被删除的 Defender 目录、
  不会重置服务 Start 值与策略键。打补丁行为不受影响，系统可持续维护。
- **安全智能更新**：仅更新定义与引擎文件。引擎二进制已不存在，更新无落点。
- **大版本就地升级（功能更新/ISO 覆盖安装）**：本质是一次重装，全部定制会被
  新版本覆盖。正确做法是用本工具对新版本 ISO 重新执行流水线（见第 8 章）。

## 7.4 约束红线

以下约束不可违反。违反任意一条即视为定制失败，必须中止并报告：

1. 仅使用 DISM / reg.exe / oscdimg.exe 及 Windows 内置命令；禁止引入任何第三方
   "系统优化/精简"工具。
2. 禁止 `dism /cleanup-image /startcomponentcleanup` 与 `/resetbase`；
   禁止删除或修改 WinSxS 内容。
3. 除白名单（第 5 章清单）外，禁止删除任何系统组件、驱动、预配 AppX、字体、
   运行库；.NET / VC++ / DirectX 全部保留。
4. 禁止禁用或删除 `wuauserv`、`CryptSvc`、`DcomLaunch` 及任何网络/存储栈服务。
5. 禁止停止 `mpssvc` / `BFE` 服务；防火墙仅以策略关闭。
6. 禁止触碰激活、ei.cfg、产品密钥相关内容。
7. 所有脚本幂等：重复执行不报错、不重复写键。
8. 全程写日志；每步完成输出 `[OK]/[FAIL]`；失败即卸载配置单元、`/discard`
   卸载映像并中止。
9. 源 ISO 只读；所有修改仅发生于工作副本。

## 7.5 安全后果的明确说明

移除 Defender、关闭防火墙与 SmartScreen 会显著削弱系统防护。产物镜像仅适用于
隔离的固件/驱动/底层开发环境，不应用于日常办公、生产环境或不可信网络。
使用 `DisableSpectreMeltdownMitigations` 开关会进一步移除 CPU 微码级漏洞缓解，
仅在性能敏感的受控测试场景考虑开启。
