# 第 8 章 适配新版 Windows 11 的维护指南

微软每次发布 Windows 11 新版本（或每次重新生成介质）后，旧的定制镜像即失去意义：
功能更新属于重装行为，不会保留离线定制。正确做法是对新版 ISO 重新执行流水线。
本章给出适配新版介质时的标准作业流程与常见差异点。

## 8.1 标准重做流程

1. 从微软官方渠道获取新版 ISO（Media Creation Tool 或软件下载中心）；
2. 核对并修改 `config.ps1` 中的 `$IsoPath`、`$EditionName`（见 8.2）；
3. 删除旧工作目录（`$WorkDir`），避免旧副本的幂等标记干扰；
4. 执行 `run-all.ps1`，完成后执行 `06-verify.ps1`；
5. 在虚拟机中按第 6 章验收清单验证。

## 8.2 版本名匹配

新版介质的版本名可能变化。匹配失败的特征是 01 步报错
"edition ... matched 0 index(es)"，并列出全部索引名。此时将列出的目标版本名
原样填入 `$EditionName` 即可。注意中文介质的版本名为中文，且 `config.ps1`
必须保持 UTF-8 with BOM 编码（见第 2 章 2.1 节）。

## 8.3 新版介质的已知差异点

| 差异点 | 现象 | 工具行为 |
|---|---|---|
| ESD / WIM 形态变化 | sources 下是 install.esd 或 install.wim | 01 步自动识别，无需干预 |
| 版本索引表变化 | 索引数量与名称变化 | `Get-EditionIndex` 要求唯一精确匹配，歧义即中止 |
| `drivers\wd` 不存在 | 新版镜像将 Defender 驱动移出该目录 | 摘除时记录"已缺席，跳过" |
| SecHealthUI 分发方式变化 | 无同名预配包或 SystemApps 目录名变化 | 预配包按 DisplayName 匹配；SystemApps 目录缺席即跳过 |
| `efisys_noprompt.bin` 缺失 | 个别介质仅有 `efisys.bin` | 05 步自动回退并告警 |
| Defender 键 ACL 变化 | 新增受保护键 | ACL 放松机制按访问拒绝自动触发 |

## 8.4 脚本自身的演进建议

若新版镜像出现工具未覆盖的差异（例如新的 Defender 组件目录名），推荐做法：

1. 先在挂载映像中人工确认新路径（02 步挂载后检查）；
2. 将新路径补入 03-customize.ps1 的摘除清单，并在 06-verify.ps1 中补充对应断言；
3. 在本文档第 5 章清单中登记该路径及其出现版本；
4. 重跑流水线与核查。

所有清单均为白名单制：新增项必须显式登记，禁止以通配符方式扩大删除范围。

## 8.5 版本归档建议

- 每个版本的定制产物与当时使用的 `config.ps1` 一并归档；
- 源 ISO 与产物 ISO 分目录存放，产物命名包含版本信息
  （例如 `Win11_25H2_Dev.iso`）；
- 保留 `customize.log` 与 `acceptance-checklist.txt`，作为该次定制的审计记录。
